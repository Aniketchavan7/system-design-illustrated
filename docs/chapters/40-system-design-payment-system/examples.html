Stripe · Idempotency and ledger reconciliation

Stripe reported $1.9 trillion in total volume for 2025. Its February 2024 engineering article reports greater than 99.999% Stripe API availability over the preceding Black Friday through Cyber Monday period. The availability figure describes that event window. 2025 annual letter · Stripe Ledger engineering write-up

In API v1, once endpoint execution begins, Stripe can save the response status and body under an idempotency key. While the key is retained, a compatible retry can return that saved result. A validation error before endpoint execution is an example of a result Stripe does not save. Stripe idempotent requests

Stripe describes Ledger as an immutable event log that represents money movement across its systems and financial partners. Its data quality platform checks flows for clearing, timeliness, and completeness. These checks address what happens after calls to payments APIs. Stripe Ledger engineering write-up

PayPal · Retrying a capture

PayPal documents the PayPal-Request-Id header for supported REST API operations. It gives payment capture as an example of an operation that can time out after being processed. Retrying with the same ID can return the status of the previous operation. Check the endpoint for support and retention. PayPal idempotency guide

Worked example · A response is lost

This is an illustrative merchant design. Write the operation ID before the first request. Reuse it when the outcome is unknown, follow the provider's recovery guidance, and reconcile unresolved attempts against provider status and settlement records. A retry after the provider's retention window needs another way to establish the original outcome before issuing a new charge.
