1. Powers of Two & Data Scale

Computers operate in base 2. In system design, memory, disk, and network throughput are calculated using powers of 2.

Power of 2 Exact Value (Bytes) Approximation Shorthand Real-World Scale Equivalent
210 1,024 1,000 1 KB (Kilobyte) 1-page plain text file (≈ 2 KB)
220 1,048,576 1,000,000 (106) 1 MB (Megabyte) 1 smartphone photo compressed (≈ 2 MB)
230 1,073,741,824 1,000,000,000 (109) 1 GB (Gigabyte) 1 pickup truck filled with books
240 1,099,511,627,776 1,000,000,000,000 (1012) 1 TB (Terabyte) All books in a major university library
250 1,125,899,906,842,624 1015 1 PB (Petabyte) 13.3 years of HD video streaming
260 1,152,921,504,606,846,976 1018 1 EB (Exabyte) 50% of all words spoken by humans in history
270 1,180,591,620,717,411,303,424 1021 1 ZB (Zettabyte) Annual global internet data traffic
280 1,208,925,819,614,629,174,706,176 1024 1 YB (Yottabyte) All digital data on planet Earth

Pro Tip (Binary vs Decimal prefixes): In networking: 1 Gbps = 109 bits/sec (Decimal). In RAM/Storage: 1 GiB = 230 bytes = 1,073,741,824 bytes (Binary). In an interview, using 103, 106, 109 approximations is standard practice.

Originally compiled by Google Fellow Jeff Dean and updated for modern hardware (DDR5, PCIe Gen5 NVMe, 100GbE cloud datacenters).

Operation Real Latency Normalized to Human Scale (1 ns = 1 sec) Architectural Takeaway
L1 CPU Cache Reference 0.5 - 1 ns 1 second Single heartbeat. Always keep hot variables in CPU registers/L1.
Branch Mispredict 3 - 5 ns 4 seconds CPU instruction pipeline stalls.
L2 CPU Cache Reference 3 - 7 ns 5 seconds Fast on-die lookup.
Mutex Lock / Unlock 15 - 25 ns 20 seconds Low cost, but concurrent thread contention destroys scale.
Main Memory (RAM) Access 50 - 100 ns 1.5 minutes RAM is fast, but 100× slower than L1 cache.
Read 1 MB Sequentially from RAM 3 - 5 µs 1 hour Sequential memory reads are blazing fast (≈ 25 GB/s).
Modern NVMe SSD Random Read 10 - 30 µs 6 hours Fast, but 1,000× slower than RAM!
Read 1 MB Sequentially from NVMe 100 - 250 µs 2 days High throughput (≈ 4-7 GB/s); sequential disk is cheap.
Intra-Datacenter RTT (Same Rack / AZ) 250 - 500 µs 5 days Network RPC overhead within the same cloud data hall.
Read 1 MB Sequentially from HDD 5 - 15 ms 5 months Spinning magnetic disks must physically move arm heads.

US Cross-Country RTT (SF to NY) 40 - 65 ms 1.5 years Speed of light in fiber optic glass (≈ 200,000 km/s).
Transatlantic RTT (NY to London) 75 - 90 ms 2.5 years Undersea fiber cable crossing the Atlantic.
Transpacific RTT (SF to Singapore) 160 - 200 ms 5.5 years High latency. Requires Edge CDNs and regional databases.

There are 86,400 seconds in one day. In interviews, approximate to 100,000 (105) for quick mental math, or use 86,400 for exact numbers.

10 Million 116 QPS 100 QPS 232 QPS 580 QPS
50 Million 579 QPS 500 QPS 1,158 QPS 2,895 QPS
100 Million 1,157 QPS 1,000 QPS 2,314 QPS 5,785 QPS
500 Million 5,787 QPS 5,000 QPS 11,574 QPS 28,935 QPS

Peak Multiplier Heuristics:

  • 2× Peak: Standard baseline web application with global users evenly spread across timezones.
  • 3× to 5× Peak: Single-country or regional application (e.g., food delivery lunch rush or ride-sharing commute hours).
  • 10× to 50× Peak: Event-driven flash sales (Black Friday, Ticketmaster stadium tour drops, Super Bowl ad).

5. The Universal 5-Step Sizing Formulas

Every system design calculation follows these 5 sequential steps:

[ Step 1: Throughput (QPS) ]
              │
              ▼
[ Step 2: Storage (5-Year Capacity) ]
              │
              ▼
[ Step 3: Network Bandwidth (Ingress / Egress) ]
              │
              ▼
[ Step 4: Memory / Cache (80/20 Rule) ]
              │
              ▼
[ Step 5: Server Cluster Count ]

Step 1: Throughput & QPS

Average Read QPS = (Daily Active Users (DAU) × Reads per User per Day) / (86,400)
Average Write QPS = (DAU × Writes per User per Day) / (86,400)
Peak QPS = Average QPS × Peak Multiplier (2× to 5×)

Step 2: Storage Sizing (5-Year Capacity)

Calculate raw daily storage, scale to 5 years, add 3× database replication, and include a 70% storage headroom safety buffer:

Daily Raw Storage = Daily Writes × Average Payload Size
5-Year Raw Storage = Daily Raw Storage × 365 × 5
Total Production Storage = (5-Year Raw Storage × Replication Factor (typically 3)) / (0.70 (Headroom Factor))

Rule of thumb: 365 × 5 ≈ 1,825 ≈ 2,000× daily storage.

Step 3: Network Bandwidth

Network cards measure in bits per second (bps), while data storage is measured in bytes (B). Always convert bytes to bits by multiplying by 8:

Ingress Bandwidth (Bytes/s) = Write QPS × Average Write Payload Size
Egress Bandwidth (Bytes/s) = Read QPS × Average Read Payload Size
Network Line Bandwidth (bps) = Bandwidth (Bytes/s) × 8

Example: 12.5 MB/s × 8 = 100 Mbps.

Step 4: Memory & Cache Sizing (80/20 Rule)

According to the Pareto Principle, 20% of entities (popular posts, active users, top videos) generate 80% of traffic. We cache that 20% hot working set in RAM:

Daily Read Working Set = Daily Read Requests × Payload Size
Target Cache Size (RAM) = Daily Read Working Set × 0.20

Add a 25% safety margin for Redis key overhead and memory fragmentation.

Step 5: Server Cluster Sizing

Required Servers = ≤ft\lceil (Peak QPS) / (Single Server QPS Capacity) \right\rceil × Redundancy Factor (1.5 to 2.0)

6. High Availability: "The Nines" & Downtime

Service Level Agreements (SLAs) determine allowable downtime:

Availability Level Downtime per Year Downtime per Month (30d) Downtime per Week Downtime per Day Typical System Classification
90% ("One Nine") 36.5 days 72.0 hours 16.8 hours 2.4 hours Batch prototype, non-critical cron
99% ("Two Nines") 3.65 days 7.20 hours 1.68 hours 14.4 minutes Internal tooling, dev environments
99.9% ("Three Nines") 8.76 hours 43.8 minutes 10.1 minutes 1.44 minutes Standard SaaS, consumer apps
99.99% ("Four Nines") 52.6 minutes 4.38 minutes 1.01 minutes 8.64 seconds Cloud infrastructure (AWS S3, Stripe)
99.999% ("Five Nines") 5.26 minutes 25.9 seconds 6.05 seconds 864 ms Telco carriers, core banking, hospitals
99.9999% ("Six Nines") 31.5 seconds 2.59 seconds 605 ms 86.4 ms Google TrueTime, aerospace avionics

Error Budget Formula:

Error Budget = 100% - SLO

If your SLO is 99.9% over 30 days, your error budget is 43.8 minutes of downtime. If breached, deployments are frozen to focus on reliability.

8. Mental Math Tricks for the Interview

  1. The 105 Day Trick: 86,400 seconds/day ≈ 105 seconds/day. To find QPS from daily requests: divide by 100,000. Example: 500M requests/day / 100,000 = 5,000 QPS (exact is 5,787; within 15%, completely acceptable).

  2. The Exponent Addition Rule:

10^A × 10^B = 10A+B

Example: 200 bytes (2 × 102) × 1 Billion writes (109) = 2 × 1011 bytes = 200 GB.

  1. Mega- to Giga- to Tera-:

    • Million (106) × Kilobyte (103) = Gigabyte (109).
    • Million (106) × Megabyte (106) = Terabyte (1012).
    • Billion (109) × Kilobyte (103) = Terabyte (1012).
    • Billion (109) × Megabyte (106) = Petabyte (1015).

  2. Bandwidth Byte-to-Bit Conversion:

Bytes/s × 8 = bits/s
  • 1 MB/s = 8 Mbps
  • 125 MB/s = 1 Gbps
  • 1.25 GB/s = 10 Gbps
